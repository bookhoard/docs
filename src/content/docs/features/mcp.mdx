Bookhoarder has a built-in [MCP](https://modelcontextprotocol.io) endpoint at
`/api/mcp`. Connect an MCP client such as Claude to it and you can say
things like "find my unread Stoker books", "fix the author on Dracula",
or "put everything I rated five stars on a new shelf" — and it happens in
your library.

There's nothing to install or turn on. The endpoint is part of the app,
and it works the same on Docker, Kubernetes, and a plain `pnpm start`.

<Aside type="caution">
  The MCP endpoint has **no login**, just like the rest of the app. Anyone
  who can reach your Bookhoarder can use it. Keep Bookhoarder on a private
  network such as [Tailscale](https://tailscale.com), or put it behind a
  reverse proxy that handles authentication.
</Aside>

## Connect a client

Settings → MCP shows these commands filled in with your own address, with
a copy button on each.

<Steps>
  <Step title="Find your endpoint address">
    It's your Bookhoarder address plus `/api/mcp`, for example
    `http://books.tailnet-name.ts.net:3000/api/mcp`.
  </Step>
  <Step title="Add it to your client">
    For Claude Code, run this once:

    ```sh
    claude mcp add --transport http bookhoarder http://localhost:3000/api/mcp
    ```

    For Claude Desktop, add this to `claude_desktop_config.json` and restart
    the app. It uses the small `mcp-remote` helper, which runs on your own
    computer. `--allow-http` is only needed for plain `http://` addresses:

    ```json
    {
      "mcpServers": {
        "bookhoarder": {
          "command": "npx",
          "args": ["-y", "mcp-remote", "http://localhost:3000/api/mcp", "--allow-http"]
        }
      }
    }
    ```
  </Step>
  <Step title="Ask for something">
    Try "which books do I have by Mary Shelley?" or "what's trending
    this week?".
  </Step>
</Steps>

### Where it can and can't connect

The client has to be able to reach your Bookhoarder address. Claude Code and
Claude Desktop (through `mcp-remote`) run on your own computer, so a
private address such as a Tailscale name works fine.

Claude on the web and the Claude mobile app connect from Anthropic's
servers instead, so they can't reach a private address. They only work if
you expose Bookhoarder to the internet — and because the endpoint has no
login, don't do that without something in front of it that does.

## What it can do

The tools match what you can do in the app. Read-only tools are marked so
your client can approve them automatically.

| Area | Tools |
| --- | --- |
| Books | `search_books`, `get_book`, `add_book_from_url`, `update_book_metadata`, `delete_book`, `set_book_state`, `send_book_to_ereader` |
| Discover | `find_metadata_candidates`, `find_similar_books`, `get_trending_books` |
| Shelves | `list_shelves`, `create_shelf`, `update_shelf`, `delete_shelf`, `add_book_to_shelf`, `remove_book_from_shelf` |

Read-only: `search_books`, `get_book`, `find_metadata_candidates`,
`find_similar_books`, `get_trending_books`, and `list_shelves`.

A few things to know:

- **Adding books.** `add_book_from_url` downloads an EPUB from a direct
  link and adds it, the same as an upload. The upload size limit in
  Settings → Library applies, and a book that is already in the library is
  not added twice. Claude can't upload a file from your computer through
  MCP.
- **Updates are partial.** `update_book_metadata` only changes the fields
  you send. `tags` replaces the whole tag list, `series: null` takes the
  book out of its series, and `coverUrl` downloads a new cover. To fix a
  book from a metadata lookup, run `find_metadata_candidates`, then send
  the match you like to `update_book_metadata`.
- **`set_book_state`** sets your rating (1–5, or 0 to clear), read flag,
  and progress (0–100).
- **`send_book_to_ereader`** emails the book to the e-reader address of
  the MCP profile. It needs SMTP set up in Settings → E-Reader Email.
- **`delete_book`** only works when the MCP profile is an admin, the same
  rule as the app.
- **Not included:** profiles and passwords, settings changes, backups, and
  the in-browser reader.

## Which profile it acts as

Ratings, read status, shelves, and the e-reader address belong to a
profile, and the MCP endpoint has no browser session to tell it which one.
By default it acts as your **first admin profile**. To use a different
one, set the `MCP_PROFILE_ID` environment variable to that profile's ID
and restart:

```sh
MCP_PROFILE_ID=3f6c1d52-8a0e-4c35-9c43-3d7f3a3c2a10
```

Profile IDs are in the `GET /api/profiles` response. If the ID doesn't
match any profile, MCP requests fail with an error that says so.

## The read-only demo

The public demo blocks every write, and MCP requests are blocked with them.
Self-host Bookhoarder to try it on your own library.

## Security notes

Besides the missing login, the endpoint refuses any request that carries
an `Origin` header for a different site, so a web page you have open can't
use it. MCP clients such as Claude Code don't send that header, so they're
not affected. This does not replace keeping Bookhoarder off the public
internet.
