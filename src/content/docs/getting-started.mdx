Bookhoard ships as a single container. Object storage is the only
persistence layer — no database, no schema, nothing to migrate — so
deploying is really just: pick where the books live, then start the
container.

## Prerequisites

- Docker Engine 24+ (or Docker Desktop), with the Compose plugin if you're
  using `docker compose`
- An object storage destination — local disk needs nothing extra; S3 or
  R2 need a bucket and a set of credentials

<Aside type="note" title="No database service">
  You will not find a database in any of the examples below. Bookhoard
  reads and writes books, covers, and profile data straight to the
  storage backend you configure.
</Aside>

## Pick a storage backend

Bookhoard talks to storage through one driver, selected with
`STORAGE_DRIVER`. All three options below run through the exact same
container image — only the environment variables change.

<Tabs syncKey="storage-backend">
  <TabItem label="Local disk">
    The simplest option for a single-machine setup. Bookhoard writes
    directly to a directory inside the container, so mount a volume to
    persist it across restarts.

    ```sh
    docker run -d \
      --name bookhoard \
      -p 3000:3000 \
      -v bookhoard_data:/app/.data \
      -e STORAGE_DRIVER=local \
      ghcr.io/bookhoard/bookhoarder:latest
    ```

    | Variable            | Required | Notes                                             |
    | ------------------- | -------- | -------------------------------------------------- |
    | `STORAGE_DRIVER`    | Yes      | `local`                                             |
    | `LOCAL_STORAGE_PATH` | No      | Defaults to `./.data`, resolved against `/app` — leave it as-is and mount `/app/.data` |

    <Aside type="caution" title="Mount the volume">
      Skip the `-v` flag and every book disappears the next time the
      container is recreated — the writable layer isn't persisted.
    </Aside>
  </TabItem>

  <TabItem label="S3">
    Works with real AWS S3 and any S3-compatible store — MinIO,
    Backblaze B2, and Cloudflare R2 (see the R2 tab for R2-specific
    setup). The container itself never needs a volume; state lives in
    the bucket.

    ```sh
    docker run -d \
      --name bookhoard \
      -p 3000:3000 \
      -e STORAGE_DRIVER=s3 \
      -e S3_BUCKET=bookhoard \
      -e S3_ACCESS_KEY=<YOUR_ACCESS_KEY> \
      -e S3_SECRET_KEY=<YOUR_SECRET_KEY> \
      -e S3_REGION=<YOUR_BUCKET_REGION> \
      ghcr.io/bookhoard/bookhoarder:latest
    ```

    | Variable        | Required | Notes                                                             |
    | ---------------- | -------- | ------------------------------------------------------------------ |
    | `STORAGE_DRIVER` | Yes      | `s3`                                                                |
    | `S3_BUCKET`      | Yes      | Bucket name                                                         |
    | `S3_ACCESS_KEY`  | Yes      | Access key ID                                                       |
    | `S3_SECRET_KEY`  | Yes      | Secret access key                                                   |
    | `S3_ENDPOINT`    | No       | Required for MinIO/B2/R2; leave unset for real AWS S3               |
    | `S3_REGION`      | No       | Must match the bucket's real region on AWS; leave unset for MinIO/R2 (they use `auto`) |
    | `S3_PREFIX`      | No       | Scope all of Bookhoard's data under a subdirectory, so the bucket can be shared with other apps |

    <Aside type="tip" title="Testing locally with MinIO">
      Bookhoard's own repo ships a `docker-compose.yml` that starts the
      app alongside a local MinIO instance and creates the bucket
      automatically — a quick way to try the S3 path without a real
      cloud account. Clone [the repo](https://github.com/bookhoard/bookhoarder)
      and run `docker compose up`.
    </Aside>
  </TabItem>

  <TabItem label="Cloudflare R2">
    R2 is S3-compatible, so it runs through the same `s3` driver as any
    other S3-compatible store — point `S3_ENDPOINT` at your account's R2
    API and go.

    <Steps>
      <Step title="Create a bucket">
        In the Cloudflare dashboard, go to **R2 Object Storage** and
        create a bucket (for example, `bookhoard`).
      </Step>
      <Step title="Create API credentials">
        From the bucket's **Settings**, create an **API token** scoped
        to R2, with **Object Read & Write** permissions. Note the
        **Access Key ID**, **Secret Access Key**, and your **Account ID**.
      </Step>
      <Step title="Run the container">
        ```sh
        docker run -d \
          --name bookhoard \
          -p 3000:3000 \
          -e STORAGE_DRIVER=s3 \
          -e S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com \
          -e S3_BUCKET=bookhoard \
          -e S3_ACCESS_KEY=<YOUR_ACCESS_KEY> \
          -e S3_SECRET_KEY=<YOUR_SECRET_KEY> \
          ghcr.io/bookhoard/bookhoarder:latest
        ```
      </Step>
    </Steps>

    | Variable        | Required | Notes                                                    |
    | ---------------- | -------- | ---------------------------------------------------------- |
    | `STORAGE_DRIVER` | Yes      | `s3` — R2's native binding mode (`r2`) only works when Bookhoard itself runs on Cloudflare Workers, not in Docker |
    | `S3_ENDPOINT`    | Yes      | `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`             |
    | `S3_BUCKET`      | Yes      | Bucket name                                                 |
    | `S3_ACCESS_KEY`  | Yes      | R2 API token access key ID                                  |
    | `S3_SECRET_KEY`  | Yes      | R2 API token secret access key                               |
    | `S3_REGION`      | No       | Leave unset — R2 uses `auto`                                 |
    | `S3_PREFIX`      | No       | Scope Bookhoard's data under a subdirectory of a shared bucket |

    <Aside type="note" title="Why S3 mode, not R2 mode">
      Bookhoard has a second, native R2 driver (`STORAGE_DRIVER=r2`), but
      it talks to R2 through a Workers binding — it only exists for
      deploying Bookhoard itself to Cloudflare Workers. A Docker
      container always reaches R2 over its S3-compatible API, so use
      `STORAGE_DRIVER=s3` here.
    </Aside>
  </TabItem>
</Tabs>

## Or use Docker Compose

For anything past a one-off `docker run`, put the environment in a
`docker-compose.yml` instead:

```yaml title="docker-compose.yml"
services:
  app:
    image: ghcr.io/bookhoard/bookhoarder:latest
    ports:
      - "3000:3000"
    environment:
      STORAGE_DRIVER: s3
      S3_ENDPOINT: https://<ACCOUNT_ID>.r2.cloudflarestorage.com
      S3_BUCKET: bookhoard
      S3_ACCESS_KEY: <YOUR_ACCESS_KEY>
      S3_SECRET_KEY: <YOUR_SECRET_KEY>
    restart: unless-stopped
```

Swap the `environment:` block for whichever backend you picked above —
add a `volumes:` entry instead if you're using the local driver.

```sh
docker compose up -d
```

## Open Bookhoard

Visit `http://localhost:3000`. The first profile you create becomes an
admin; additional profiles can be added from settings, with optional
per-profile passwords.

## Environment reference

| Variable              | Default    | Used by         |
| ---------------------- | ---------- | ---------------- |
| `STORAGE_DRIVER`       | `local`    | all              |
| `LOCAL_STORAGE_PATH`   | `./.data`  | `local`          |
| `S3_ENDPOINT`          | —          | `s3`             |
| `S3_BUCKET`            | —          | `s3`             |
| `S3_ACCESS_KEY`        | —          | `s3`             |
| `S3_SECRET_KEY`        | —          | `s3`             |
| `S3_REGION`            | —          | `s3`             |
| `S3_PREFIX`            | —          | `s3`             |
| `SMTP_URL`             | —          | send-to-e-reader |
| `OPENLIBRARY_CONTACT`  | —          | metadata lookups |

<Aside type="tip" title="Open Library rate limits">
  Set `OPENLIBRARY_CONTACT` to an email or contact URL — identified
  requests get a 3x higher rate limit (3 req/s vs 1 req/s) for metadata
  and cover lookups.
</Aside>
